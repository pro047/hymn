# 단계: 판단 검증

기능: $FEATURE

설계 문서의 **주장**을 감사한다. 설계를 고치는 단계가 아니고, 구현 품질을 보는
단계도 아니다. **"이 문서가 사실이라고 말한 것들이 실제로 사실인가"** 하나만 본다.

이 단계가 있는 이유: 구현물은 테스트·리뷰·게이트를 통과하는데 **판단물(원인 판정,
우선순위, "X가 없다")은 아무 검증 없이 다음 단계로 흘러간다.** 틀린 1순위는 틀린
코드보다 비싸다 — 며칠을 엉뚱한 곳에 쓰게 만든다.

## 출력 (이 파일 하나만 쓴다)
$WORK/JUDGE.md

## 입력 (읽기만, 절대 수정 금지)
- `$WORK/DESIGN.md` — 감사 대상
- `$ROOT/.claude/handoff.md` — **이 저장소의 결정 이력·지뢰 정본.**
  특히 1-A절의 "**반증된 것 — 다시 안 봐도 되는 영역**" 과 상단 블록의 "**반증된 것**" 목록.
  **설계가 거기 반증된 주장을 되살렸다면 그것만으로 `반박`이다** — 재확인할 필요도 없다.
  반대로 handoff 가 `실측` 으로 적어둔 것은 근거로 인정한다(날짜를 함께 인용할 것).
- `$ROOT/.claude/research-*.md` — 있으면 읽는다. 최근 측정값의 출처다

## 할 일

1. `$WORK/DESIGN.md` 에서 **하중을 받는 주장**을 전부 뽑는다. 하중을 받는다 =
   그게 틀리면 설계의 방향·순서·범위가 바뀐다.
   - 원인 판정 ("느린 이유는 N+1 쿼리다")
   - 우선순위·순서 근거 ("A 를 먼저 해야 한다")
   - 부재 주장 ("이 기능은 없다", "로깅이 없다", "테스트가 없다")
   - 현재 동작 주장 ("이 API 는 500 을 반환한다")
   - 비용·성능·보안 주장 (숫자를 동반하는 것)
   - 외부 스펙·라이브러리 동작 주장

   설계 취향(네이밍, 파일 배치)이나 아직 만들지 않은 것에 대한 계획은 대상이 아니다.

2. 각 주장에 **근거 등급**을 매긴다.
   - `실측` — 도구를 실제로 돌린 출력이 근거
   - `코드확인` — `파일:줄` 로 짚을 수 있음
   - `추정` — 위 둘이 아닌 전부 (관례·유추·문서만 읽음·그럴듯함)

3. **확인이 가능한 주장은 직접 확인한다.** 이게 이 단계의 본론이다.
   `$ROOT` 에서 grep/테스트/스크립트를 돌려 재현한다. 확인 비용이 도구 호출
   1~2회면 반드시 한다. 문서만 읽고 넘기지 않는다.
   - **DESIGN.md 가 `파일:줄` 을 적어둔 주장은 그 좌표로 직행한다.** 저장소를 다시
     탐색해서 같은 것을 찾아내지 마라 — 좌표가 틀렸으면 그 자체가 발견이다.
   - **저장소 전수 탐색은 부재 주장 전용이다.** 아래 전수 확인은 절대 생략하지 않는다
     — 여기서 아끼는 것은 "이미 좌표가 있는 것을 다시 찾는 비용"뿐이다.
   - 부재 주장은 **전수 확인**한다. 서비스·언어가 여러 개면 전부 본다
     (한쪽만 grep 하고 "없다"고 한 것이 실제로 자주 나오는 오류다).
     **이 저장소는 백엔드(Python)·프론트(React)·앱(Flutter) 셋이다 — 셋 다 본다.**
     `hymn_app/` 은 중첩된 별도 git 저장소라 루트 grep 에서 빠질 수 있으니 명시적으로 포함한다
   - 숫자 주장은 산수를 해본다. 자릿수가 맞는지만 봐도 죽는 주장이 많다

   **★ 도구가 거부되면 우회하지 말고 즉시 `미확인` 으로 센다.**
   이 단계는 보통 **tty 없는 백그라운드(런처 모드)로 돈다** — 네트워크 호출·임의 스크립트
   실행은 승인을 받을 수 없어 거부된다. 그때 다른 명령·다른 도구로 갈아타며 재시도하면
   **예산만 태우고 결국 같은 곳에 도착한다**(2026-08-24 실측: `curl`→단일 `curl`→`python3`→
   `WebFetch` 4회 왕복 끝에 예산 초과로 죽어 산출물 0). 한 번 거부되면 그 경로는 닫힌 것이다.
   `미확인` 으로 세고 **"무엇을 실행하면 확인되는지"** 를 적어 사람에게 넘겨라 —
   그게 이 단계가 할 일이고, 우회는 아니다.

   **운영 수치는 다시 재지 않는다. 이미 측정돼 문서에 있다.**
   `.claude/research-transpose-feasibility-2026-08-23.md` **§1(운영 데이터 실측)** 과
   **§2(해상도 분포)** 에 `GET /api/scores` 전수 측정 결과가 근거와 함께 들어 있다 —
   행 수·고유 제목 수·고유 파일 수·주차 수·sha256 중복·저장 용량.
   **이것을 `실측` 등급으로 인용한다**(날짜를 함께 적을 것). 같은 수치를 네트워크로 다시
   받으려 하지 마라. 문서와 설계가 어긋나면 그건 **`반박`** 이고, 문서에 없는 수치를 설계가
   주장하면 **`미확인`** 이다.

   **이 저장소에서 실제로 쓸 수 있는 확인 경로 (전부 로컬·읽기 전용):**
   - **코드 확인** — `grep` / `Read`. 이 단계 주장의 대부분은 여기서 판정된다
   - **마이그레이션 계보** — `backend/alembic/versions/` 를 grep (`^revision` / `^down_revision`).
     `alembic heads` 는 DB 연결이 필요하니 파일 grep 을 먼저 쓴다
   - **테스트 실행** — 거부되지 않았다면 `cd backend && .venv/bin/python -m pytest -q`.
     **거부되면 즉시 `미확인`** (위 규칙)
   - **dev 백엔드·docker** — 컨테이너를 띄우려 하지 말 것. 안 떠 있으면 `미확인`

   **AWS·테라폼은 건드리지 않는다.** `terraform plan` 은 워크스페이스를 잘못 잡으면
   운영에 31개 생성을 시도하고, `rds_password` 프롬프트에 틀린 값을 넣으면 운영 DB
   비밀번호가 바뀐다(handoff 1-A절). 인프라 주장은 `미확인` 으로 세고 사람에게 넘긴다.

4. 확인 결과를 판정으로 적는다.
   - `확인` — 주장이 맞다 (재현 방법·출력 요약을 남긴다)
   - `반박` — 주장이 틀리다 (**무엇이 실제인지**와 근거를 남긴다)
   - `미확인` — 이 단계에서 확인 못 했다 (**왜** 못 했는지, 누가 무엇을 하면
     확인되는지 남긴다)

## JUDGE.md 필수 형식

**★ 산출물을 마지막에 몰아 쓰지 마라.** 하중받는 주장을 다 뽑고 **확인을 시작하기 전에**
`STATUS`·카운트·주장 표(판정은 `미확인` 으로 초기화)를 **먼저 한 번 써라.** 그 뒤 확인이
끝날 때마다 그 파일을 갱신한다. 이유: 예산이나 턴이 끊기면 **마지막에 쓰려던 것은 통째로
사라진다** — 2026-08-24 에 확인을 다 마치고 Write 하는 순간 예산이 끊겨 $5 를 쓰고 산출물이
0 이었다. 초안이 있으면 최소한 "무엇을 확인하려 했고 어디까지 갔는지" 는 남는다.
**중간 저장본의 카운트는 항상 정직해야 한다** — 아직 확인 안 한 것은 `미확인` 이다.

첫 줄은 STATUS 라인. 그 다음 줄에 **기계가 읽는 카운트 한 줄**을 정확히 이 형식으로:

```
STATUS: DONE
UNVERIFIED: <미확인 개수> REFUTED: <반박 개수>
```

파이프라인 셸이 이 숫자를 파싱한다. **하나라도 0 이 아니면 사람 게이트가 뜬다**
(무인 실행이어도 멈춘다). 숫자를 낮게 쓰려고 판정을 무르게 하지 말 것 — 그건
이 단계를 무의미하게 만드는 유일한 방법이다. 애매하면 `미확인` 으로 센다.

이어서 주장별 표를 쓴다.

| # | 주장 (원문 인용) | 등급 | 판정 | 근거 / 실제 |
|---|---|---|---|---|

마지막에 다음 두 절을 반드시 쓴다.

- **구현 전에 해소해야 할 것** — `반박` 과, 방향을 바꿀 수 있는 `미확인`.
  각 항목에 "무엇을 하면 풀리는지" 를 적는다
- **그대로 진행해도 되는 것** — 틀려도 손해가 작은 `미확인`. 왜 작은지 한 줄

## 금지

- **설계 문서를 수정하지 않는다.** 틀린 게 있으면 JUDGE.md 에 적을 뿐이다
- **코드를 수정하지 않는다.** 확인을 위한 읽기·실행만 한다. 확인용 임시 파일을
  만들었으면 지운다
- 주장이 없는데 억지로 채우지 않는다. 하중받는 주장이 0 개면 그렇게 쓴다
- **"통과했습니다" 로 끝내지 않는다.** 확인하지 않은 것을 `확인` 으로 적는 것이
  이 단계의 유일한 실패 모드다. 확인 못 했으면 `미확인` 이 정답이다
- 설계 자체가 읽을 수 없거나 하중받는 주장을 판별할 수 없으면 `STATUS: BLOCKED`
